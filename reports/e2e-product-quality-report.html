03 Bugs found & fixed

High1 Medium3 Low2 All fixed · regression-locked
High BUG-001 Timestamps serialized without a UTC offset Fixed

Backend · API serialization

User impact
In any timezone east of UTC, a just-sent message shows a stale time (e.g. “5h” in IST) instead of “now”; conversation-list and connection times are all wrong. Every displayed time is untrustworthy.
Root cause
DateTime values read from SQLite have Kind=Unspecified, so System.Text.Json writes them with no offset (2026-07-20T17:14:04.566). The browser parses an offset-less ISO string as local time.
Fix
Global JsonConverter<DateTime> that treats Unspecified/Local as UTC and always writes the round-trip “O” format (trailing Z). Fixes every client at once; no DTO changes.
Files changed
  • backend/src/Saha.API/Serialization/UtcDateTimeJsonConverter.cs (new)
  • backend/src/Saha.API/Extensions/ServiceCollectionExtensions.cs
Regression
regression.spec.ts — API (timestamp format) + UI (“now”) — fails before the fix, passes after.
Medium BUG-005 Wrong-password login shows “Refresh token not found.” Fixed

Frontend · axios interceptor

User impact
On the most common auth failure, the toast read “Refresh token not found.” instead of “Invalid username or password.”
Root cause
The 401 interceptor excluded only /auth/refresh, so a 401 from /auth/login triggered a spurious token refresh whose own error replaced the real one.
Fix
Refresh-retry now skips all unauthenticated auth entry points; /auth/session still refreshes on 401.
Files changed
  • frontend/src/core/api/axios-instance.ts
Regression
auth.spec.ts — “wrong password … real error message” — fails before the fix, passes after.
Medium BUG-003 Incomplete couple can send connection requests Fixed

Backend · Connect

User impact
An AwaitingPartner couple could create a request that is invisible to the target yet permanently blocks a real future request between the two couples.
Root cause
SendConnectionRequest never checked requester completeness, while GetConnections silently drops connections involving incomplete couples — the invariant was assumed, never enforced.
Fix
Guard: refuse the request when the requester couple is not Complete (HTTP 409 COUPLE_INCOMPLETE).
Files changed
  • backend/src/Saha.Application/Features/Connect/Commands/SendConnectionRequest/SendConnectionRequestCommandHandler.cs
Regression
regression.spec.ts — incomplete couple refused (API) — fails before the fix, passes after.
Medium BUG-004 Pending-request badge never shows until the tab is opened Fixed

Frontend · ConnectPage

User impact
The Pending count badge — meant to alert from other tabs — only rendered after you clicked into Pending, so a fresh incoming request produced no notification.
Root cause
The pending query was gated by enabled: activeTab === "pending".
Fix
Fetch the pending count unconditionally so the badge is accurate from first load.
Files changed
  • frontend/src/modules/connect/pages/ConnectPage.tsx
Regression
regression.spec.ts — badge visible on Connected tab — fails before the fix, passes after.
Low BUG-002 Login footer renders a literal \u00b7 Fixed

Frontend · LoginPage

User impact
The app’s front door showed the raw escape text “\u00b7” between two links instead of a “·” separator.
Root cause
A literal \u00b7 sat in JSX text content, where escapes are not interpreted (unlike a JS string literal).
Fix
Replaced with a real UTF-8 “·”.
Files changed
  • frontend/src/modules/auth/pages/LoginPage.tsx
Regression
regression.spec.ts — no literal escape on /login — fails before the fix, passes after.
Low BUG-006 “Decline request” button had no accessible name Fixed

Frontend · ConnectPage (a11y)

User impact
The icon-only decline button gave screen-reader users no way to know what it does (WCAG 4.1.2).
Root cause
Icon-only <button> with no text and no aria-label.
Fix
Added aria-label="Decline request".
Files changed
  • frontend/src/modules/connect/pages/ConnectPage.tsx
Regression
connect.spec.ts — decline via accessible name — fails before the fix, passes after.
Observations (documented, not fixed): OBS-1 the auth store’s partnerName holds the current user’s own name yet is used as the partner-name fallback on the dashboard (transient wrong name before the profile query resolves); OBS-2 the first API call after a hard reload always 401s then recovers via refresh (console noise, no proactive boot refresh); OBS-3 no realtime message delivery (react-query invalidation only). The pre-existing tests/e2e/real fixtures are stale against the redesigned auth and were replaced.

06 Remaining risks & gaps

None block release; each needs external infrastructure or a product decision, and is documented in testing/COVERAGE_MATRIX.md.

  • Media & picture upload — needs Azurite / blob storage locally; message media and profile-photo upload are not automated.
  • Password reset with a real code — needs a captured mailbox; only client-side validation is automated end-to-end.
  • Mobile / tablet viewports — the messaging master/detail collapse and mobile sidebar are not yet in the automated matrix (desktop Chromium only).
  • Invite screens — /invite and /invite/accept are intentional placeholders (no approved design); verified as placeholders only.
  • Group settings dialog — rename / add-couple / pin / hide are present but not fully driven by the UI suite.
  • Observations OBS-1..3 — low-severity, documented, not fixed.
